### Historical validation before the official-input refresh

Isolated `PORTAGE_CONFIGROOT` (no host `package.use`, env hooks or user
patches). 35 `clean prepare` + `olddefconfig` + `tests/test-source-features.py`
cases (17 sources, 18 kernel): BORE, EEVDF, BMQ, PDS, MuQSS 1000 Hz full,
MuQSS 100 Hz periodic lazy + AUFS, RT, RT-BORE, deckify, AUFS, KCFI, full,
thin-dist and no LTO, staged ZFS, server preset, `-bbr3 -per-gov` and kernel
GCC; scheduler patches applied at `--fuzz=0`. Default sources `clean package`
produced a binary package; installed-image assertions pass. That initial pass did
not include kernel compilation, `modules_prepare` or boot testing.

BORE compile fix (gentoo-zh/overlay#15960 comment 6544895858): 7.3.1-1
`update_protect_slice()` uses `normalized_sysctl_sched_base_slice`, which the
pinned BORE patch hides under `!CONFIG_SCHED_BORE`. Object-only evidence with
clang 23.1.4, ThinLTO, the same isolated config root, after `clean prepare` and
`olddefconfig`: `make LLVM=1 LLVM_IAS=1 -j16 kernel/sched/fair.o`.
- Before the fix, sources `bore`: exit 2 with
  `fair.c:1175:14: error: use of undeclared identifier 'normalized_sysctl_sched_base_slice'`.
- After the fix: exit 0 for sources `bore`, `rt-bore`, `bore deckify`,
  `eevdf` (control, fix not applied) and kernel `bore`. Kernel `rt-bore`,
  `deckify` and `eevdf`: `clean prepare` + `olddefconfig` only.
- Default sources `clean package` passes; installed `fair.c` has the guard.

This is `fair.o` only. No vmlinux, module or ebuild compile. `CONFIG_RUST`
is dropped by `olddefconfig` because this host has no `bindgen`; `fair.o` is C.
Do not read this as a full-kernel build result.
